# Design — Repositioning Narrative Rollout

## Context

重定位决策（09-03 方案，Q1–Q8 已收敛）只差落地：README、插件显示名、演示物料。工程侧无可行性风险，全部是内容生产 + 少量显示层代码。已有资产：E2E 录屏/截图管线（`Pulsar.E2E`，18.6s run 已验证）、中英 resx 本地化体系、插件显示身份 spec（`plugin-display-identity`）。

## Goals / Non-Goals

**Goals:**
- 对外触点（README/插件名/演示视频）在 M1 发布前完成叙事切换，且中英一致。
- 截图/视频产出**可复现**——依托 E2E 管线而非手工截屏，内容更新时可重跑。

**Non-Goals:**
- 不动安装器/更新/打包（Change 4）、用户手册/Release 资产（Change 5）。
- 不改任何插件 Id、配置 schema、动作语义。
- 不做落地页/官网（M3 传播阶段另议）。

## Decisions

1. **插件名变更走 `GetMetadata()` + resx，不改 Id**：显示身份属 `plugin-display-identity` 能力域；Id/持久化键不动，避免用户配置迁移。备选「连 Id 一起改」被否——迁移成本与断路器/权限授权记录均受影响。
2. **截图经 E2E 管线产出**：新增专门用于宣传的工作流 JSON（复用 fixture 注入 + 截图步骤），产物落发布专用目录并入库（与「UI 验证截图 never commit」纪律区分——那是本地产物，这是发布资产）。分辨率与主题在 tasks 固化（Dark 为主）。
3. **Demo 视频三支主题锁死在「老旧系统自动化」**（09-03 叙事红线）：Excel 跑宏 / 老旧网页脚本注入 / 登录填表自动化；每支 30–60s，录屏方式，脚本先审后录。
4. **README 重写以重定位方案 §1/§3 为唯一叙事来源**，中英同步、避免「启动器」词根；AI 愿景只提一句并标注 roadmap。

## Risks / Trade-offs

- 宣传截图与未来 UI 迭代会过时——以「可重跑管线」缓解，过时重跑而非重拍。
- 视频录制依赖真实 Excel/WPS 与内网页面样例，办公环境差异可能导致画面与部分用户场景不符——脚本中用最常见的表格/登录形态降低违和感。
- 插件改名后，旧教程/旧文档引用将不一致——tasks 中包含全仓显示名引用扫描。
