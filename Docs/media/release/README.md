# Release Media Assets

Curated promotional / release screenshots and media for Pulsar. These assets
are **tracked in git** — they are the canonical first-screen images used in
README, release notes, and marketing pages.

## Boundary: what goes here vs. what never gets committed

| Location | Content | Tracked in git? |
|---|---|---|
| `Docs/media/release/` (this dir) | Curated, reviewed promotional screenshots at final resolution | **Yes** |
| `Docs/media/` (siblings of this dir) | Ad-hoc manual verification captures, may contain real profile data | No (`.gitignore`: `Docs/media/*`) |
| `Pulsar/Pulsar.E2E/artifacts/` | Raw E2E run output (full-resolution screenshots, per-run) | No (build artifact, throwaway) |

Rule of thumb: if an image is meant for external audiences (README, release
notes, website), it belongs here after review and scaling. If it is evidence
from a verification run, it stays in `artifacts/` or the ignored `Docs/media/`
siblings.

## Regeneration

These images are produced deterministically by the E2E promo pipeline:

```bash
# 1. (Re)build both projects
dotnet build Pulsar/Pulsar/Pulsar.csproj
dotnet build Pulsar/Pulsar.E2E/Pulsar.E2E.csproj

# 2. Run the one-shot wallpaper+E2E wrapper (sets pure-black wallpaper,
#    minimises all windows, runs the workflow, restores wallpaper)
powershell -NoProfile -ExecutionPolicy Bypass -File \
  "$env:TEMP\run-promo-wallpaper.ps1" -RunId promo-release-N

# 3. Scale the keepers from 2560×1440 to 1920×1080 and copy here
#    (see scripts/ or the Phase 2 journal entry for the scaling command)
```

Key files:
- Fixture: `Pulsar/Pulsar.E2E/Fixtures/promo/office-workbench-dark.json`
- Workflow: `Pulsar/Pulsar.E2E/Workflows/promo-release-screens.json`
- Raw output: `Pulsar/Pulsar.E2E/artifacts/promo-release-N/`

## Naming convention

- Prefix with a two-digit sequence number (`01-`, `02-`, …) for stable
  ordering in README and release pages.
- Use lowercase kebab-case descriptive names.
- Final deliverables are always **1920×1080 PNG** unless a different format
  is explicitly required (webp, mp4, etc.).
- Videos go in `videos/` (Phase 3).

## Review checklist before adding a new asset

1. [ ] Background is clean (no browser tabs, chat windows, or personal data)
2. [ ] Menu / UI is centred and fully rendered (no mid-animation frames)
3. [ ] Text is legible at 1920×1080 (no clipped or overlapping labels)
4. [ ] No real secrets, API keys, or personal profile data visible
5. [ ] Scaled from the raw E2E capture with high-quality resampling
6. [ ] This README updated with the new row
