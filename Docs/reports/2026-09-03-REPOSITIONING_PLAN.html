Pulsar 重新定位方案

日期：2026-09-03 状态：已确认（多轮决策收敛） 依据：市场评估报告 + 产品定位设计树（Q1–Q8）
Pulsar —— 重度办公效率工作台：
一键跑 Excel/WPS 宏、为老旧内网系统定制操作入口、安全填表登录、快速切换窗口。
Pulsar — the office automation workbench for legacy enterprise systems. Run Excel/WPS macros, script old intranet web pages, fill & sign in securely, switch windows fast.
一句话摘要：Pulsar 不再定位为"生产力启动器"，而是定位为"帮用户驯服老旧办公系统"的办公自动化工作台。核心受众是财务/运营/行政等重度办公白领；主打「自动化领衔（VBA + 老旧网页脚本）＋ 凭据护城河（PKI）＋ 窗口打底」。本轮为叙事级重定位：不动交互范式，先改定位、功能排位与产品外皮，1–2 周可落地见效。

1. 定位声明

1.1 一句话定位

  • 中文：Pulsar —— 重度办公效率工作台：一键跑宏、安全填表登录、快速切换窗口。
  • 完整叙事：让"现代工具管不了"的老旧办公系统也能自动化——Excel/WPS 跑宏、不支持插件/油猴的老旧内网网页、多系统登录与表单录入，全部变成热键/轮盘上的一键动作。
  • English：Pulsar — the office automation workbench for legacy enterprise systems. Run Excel/WPS macros, script old intranet web pages, fill & sign in securely, switch windows fast.

1.2 差异化话术（vs 竞品）

对谁话术
vs Quicker"Pulsar 不是又一个轮盘菜单，而是把重复办公操作变成一键动作的办公自动化引擎——深度支持 Excel/WPS 宏、老旧内网网页脚本与安全凭据注入，这是 Quicker 泛化动作库覆盖不到的深度。"
vs Flow / uTools / Wox"我们是鼠标+热键的办公工作台，不是搜索启动器；我们不和搜索框竞争，我们处理的是他们管不了的老系统自动化。"
vs 密码管理器"我们不只存密码，而是把登录+填表+后续动作整条链路做成一个动作，且注入方式可编程、可审计。"

2. 目标用户画像

维度画像
人群财务、运营、行政、内勤等重度办公白领（中国职场）
典型场景高频使用 Excel/WPS 做表与跑宏；登录多个老旧 OA/ERP/财务内网系统；重复录入、复制粘贴、报表汇总
技术特征不懂脚本，愿意"别人配好、自己点一下"；对安全有顾虑但极需省事；靠同事推荐与工具站发现软件
环境约束公司电脑、老旧内网系统（IE 时代）、不允许装浏览器扩展/油猴、可能无外网
核心诉求把"每天重复 N 次的操作"变成"一个动作/一个热键"；减少登录与填表的枯燥与出错

3. 价值主张三层结构

① 自动化领衔（前台主打） · VbaRunner + BookmarkletRunner
让用户最快感知价值：一键跑 Excel/WPS 宏；为不支持现代浏览器扩展/油猴的老旧内网网页，用书签脚本自定义操作入口（中国企业在大量使用上古网站，这是真实且特有的痛点）。
② 凭据护城河（差异化壁垒） · PkiPlugin
竞品几乎没有的能力：把登录、填表、注入做成可编程、可审计、DPAPI 保护的安全动作。低频感知但高频信任，是别人短期抄不走的部分。
③ 窗口打底（基础体验） · WinSwitcher + Command
每天使用的基础盘：MRU 窗口切换、命令/动作执行。不主打，但保证"打开就有用"。

System 插件保留但退居后台；办公动作预置包为新增，用于降低上手门槛。

5. 叙事红线

"驯服老旧办公系统"这一主线应贯穿所有对外触点，保持一致的场景语言：

  • README / 落地页：首屏 = 定位语 + 三支柱场景 + 真实截图/demo 视频；不再以"启动器"自居。
  • 演示视频：三支场景片——Excel 跑宏、老旧网页脚本注入、登录/填表自动化；每支 30–60 秒。
  • 传播内容：主题锁定"老旧系统自动化"（企业 OA/ERP 痛点），而非抽象的"效率工具"。
  • 插件命名/元数据：BookmarkletRunner 的可视名称向"网页脚本 / 老旧系统助手"方向对齐，本地化标签同步更新。
  • AI 愿景：叙事中作为愿景提一句，明确标注 roadmap、不承诺交付时间；路线图第一优先级立项"AI 生成 Slot 配置"PoC。

8. 与市场评估的呼应

  • 回应「引擎一流、市场缺位」：本轮 M0/M1 直接修复"无安装器/无文档/无截图"三大市场硬伤。
  • 回应「搜索/生态/AI 三块空白」：不硬碰搜索红海（Flow/uTools），用老旧系统垂直场景建立差异化；AI 以 PoC 进入路线图。
  • 回应「正面撞 Quicker」：用"办公自动化深度（VBA/老旧网页/凭据注入）"而非泛化轮盘与之区分。

9. 风险与开放问题

  • 老旧系统 UI 易变：Bookmarklet/PKI 依赖目标网页与窗口结构，系统更新可能失效 → 需要示例库、失败提示与快速反馈渠道。
  • 「老旧系统」叙事的反噬：宣传时避免显得"只解决老问题"，需同时强调"顺手的日常效率"以免窄化。
  • 安全信任门槛：凭据注入涉及高信任成本 → 需要明确的隐私/审计说明与"默认不记录"承诺。
  • 个人项目可持续性：商业化（Q8）作为中期，需在 M3 用户量起来后及时评估。
  • 开放问题：办公动作预置包的初始内容清单、BookmarkletRunner 的正式中文名、demo 视频的拍摄方式（录屏即可）——可在 M0/M2 落地时细化。
