### 踩坑：CRLF 与 `git add` 被 safecrlf 拦截（重要，可复用）

- 现象：`git add` 三个 .cs 文件报 `fatal: CRLF would be replaced by LF`，commit 无法进行。
- 根因组合：`.gitattributes` 声明 `* text=auto eol=lf`；`.git/config` 里 `core.safecrlf=true` + `core.autocrlf=false`；而这 3 个文件工作区是 CRLF。safecrlf 检测到「add 后变 LF、checkout 回来也是 LF ≠ 当前 CRLF」而拒绝。
- 背景：2026-08-27 的 `de8bfe7` 把行尾策略从「全部 CRLF」改成「全部 LF」，但当时没做 renormalize，导致这 3 个文件（9 月初手势/渲染器开发中生成）成为 CRLF 孤岛。
- **解法：`git add --renormalize <paths>`**。先量影响面（`git add --renormalize .` 后 `git diff --cached --numstat`，确认只有自己改的 6 个文件、184 行，确认安全后再 `git reset` 重新分组）。整仓其余 1166 个文件早已是 i/lf w/lf，不存在全仓问题。
- 注意：`git checkout -- <file>` **不会**把 CRLF 工作区文件重写成 LF（git 认为归一化后内容等价、跳过重写）。工作区留 CRLF 无害（status 干净、diff 正常），后续编辑照常用 `--renormalize` 暂存即可。
- 教训：并行发多个 Edit 曾有两处静默未生效，文档类多处编辑要串行 + Grep 复核。

## ADR-011：级联子菜单 Ring/Fan 布局与分页语义（commit ccfb7f5）

- 闭环验证报告最后一项文档债务「分页语义未固化」。写了 `Docs/decisions/011-cascade-submenu-layout-and-paging.md`（98 行），并同步 roadmap §4.5 风险标记、验证报告 §6、Docs 索引（decisions 10→11）。
- 语义要点（全部来自代码实证，非新增行为）：**子环与根环是两套独立页状态**（进入子菜单重置为第 0 页，退出不扰动根页）；**共享 `SlotsPerPage`**，子页数 = ceil(SubSlots.Count / SlotsPerPage)；**滚轮按菜单状态路由**（SubMenu→子环翻页，根页挂起，边界只发反馈不回绕）；**Fan 是偏好、Ring 是下限**——Fan 仅当**当前页**子项 ≤3 才生效，>3 按页回落 Ring，因此 Fan 偏好 + 5 个子项会出现「第 1 页 Ring / 第 2 页 Fan」的逐页形态切换（这是有意接受的结果，人工 QA 要按此预期核对）；**命中按页作用域**（他页子项不可命中）；子环半径 = 根环 × 比例并钳制画布安全区；**外甩取消始终用根环半径**（与钻取深度无关，语义恒为「放弃整个菜单」）；分页时中心槽追加本地化页码指示。
- 关键代码位置：`SubMenuLayoutEngine.cs`（FanMaxSlots=3 / 翼角±30° / HitTestFan 最小角差）、`CascadeSubMenuStrategy.ConfigureSubMenu`（按 PageIndex×SlotsPerPage 切窗）、`MenuSession.GetCascadePageChildCount` / `BuildCascadeParentPose` / `UpdateFlickOutEscapeState` / `HandleSubMenuMouseWheel`（MenuSession.cs:1299 按状态分发）。

## 运行时卸载/覆盖安装失败：根因与修复（commit 223a36a）
- 根因 1（DLL 锁定）：discovery 把外部插件 DLL 加载进 PluginLoadContext（isCollectible:true）但从未调用 Unload()，也没人跟踪上下文 → DLL 文件被进程锁定 → 运行中 Directory.Delete 抛 IOException。
- 根因 2（残骸死锁）：部分卸载后目录只剩 DLL（无 manifest）→ LocalPluginScanner 不列出（无卸载入口）→ IsPluginInstalled 只查目录存在 → 覆盖安装被 "already installed" 拒绝。
