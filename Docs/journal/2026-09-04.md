## 追记 (21:5x · 全量套件死锁排查与修复——K 测试落地暴露的测试基建 bug)

**现象与诊断路径**
- 首次全量（默认并行、grep 管道）15 分钟零输出 → 杀。重跑（输出落 `test_k.log`）仍挂：日志只有 2 行（testhost 启动后无任何测试完成）。

- 关键证据：detailed 日志里**从未出现 `AppStartupCoordinatorTests`**。
- 排除实验：`--filter FullyQualifiedName!~AppStartupCoordinatorTests` 全量 → **1037/1037，24 秒**。挂因锁定 K 测试。

**根因（三步链条）**
1. `ThemeServiceTests` / `SettingsSaveSessionTests` / `SettingsViewModelDirtyStateTests` / `BookmarkletScriptEditorContentSmokeTests` 都执行 `if (Application.Current == null) _ = new Application()`——`Application.Current` 是 AppDomain 全局静态，xunit collection 隔离**不隔离它**，残留到进程结束。
2. K 测试 #7 依赖「宿主中 `Application.Current` 为 null → NRE → 生产 catch 吞掉并 LogError」这一**进程全局假设**作为可观测信号。
3. 全量跑时污染已发生 → `Application.Current` 非 null → 生产代码 `await await Application.Current.Dispatcher.InvokeAsync(...)` 不再 NRE，而是把回调排进一个**永不泵消息的死 Dispatcher** → 永不完成 → 挂死。定向跑无污染所以通过。

**修复（确定性 seam）**
- `AppStartupCoordinator` ctor 新增可选 `Func<Dispatcher> dispatcherProvider = null`，默认 `() => Application.Current?.Dispatcher`（生产语义等价——同对象、无 Application 时同样 NRE 进同一 catch）；tutorial 分支改走 `_dispatcherProvider()`。
- DI 是类型注册，MS.DI 对带默认值的可选参数自动采用默认值 → `App.xaml.cs` 零改动。
- 测试注入固定 `() => null`，#7 断言/注释从「全局状态假设」改为「seam 决定论」。
- 沉淀 `Docs/lessons/XUNIT_APPLICATION_CURRENT_DEADLOCK.md`（机制 + 4 条可复用规则 + 诊断套路）。

- 重建 0 错误；定向 19/19（1s）；**全量默认并行 1045/1045（22s）**——正是最初挂死的原始配置，修复对根因彻底有效。
