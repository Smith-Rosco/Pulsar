**关键决策 / 坑**
- **根因比「重复」更深**：`SettingsEditorSession.CommitAsync` 的 secret 管线是**只增**合并（没有删除语义）——「删除」无处可去，caller 只能穿过 seam 自己落盘写 store。所以深化的关键不是「把写收敛」，而是**给 seam 补上删除这一格**（`RemoveSecretAsync`）。
- **删除语义保持不变**（原为立即落盘、不可撤销）：本候选只搬 seam 不搬行为，避免引入需要用户裁定的行为分叉；「暂存删除 → 随会话提交」是一个独立的后续决定。
- **顺带清掉死写**：原 `SecretPickerViewModel` 对 `labelMap` 的两处写入是**死写**——`BuildLegacySecretLabelMap()` 每次返回新字典，写进去无人读。已随重构删除。
- **接口面最小化裁决**：一度新增 `TryGetPendingSecret`，但 `IReadOnlyDictionary` 本身已提供 `TryGetValue` → 撤回。workspace 面只留「只读视图 + 两个命名变更方法」。
- **⚠ 工具坑（新增，跨会话有效）**：**同一条消息里对同一个文件发两处 Edit 会互相覆盖**（后写的赢，前一处静默丢失，但两处都回 "Successfully edited"）。本次因此丢了两处改动（构造器里的 seam 创建 + 字段声明删除），是靠 `git diff --numstat` 对账才发现的。→ **同一文件的多处编辑必须串行（一条消息一处）**，改完立即 `git diff` 对账。
