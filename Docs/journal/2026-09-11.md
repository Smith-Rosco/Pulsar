**关键决策 / 坑**
- **红证明（本次刻意做）**：把 `RecentDaysThreshold` 临时改回 7、并把 `UsageStatsReadModel.RelativeTimeKeyPrefix` 改成 `Settings.Bogus`，窄范围跑 → **恰好 5 条预期失败**：`Ladder_(29d)` / `(29d23h)` 吐出 `2026-08-13`、resx 守卫列出 8 个 `Settings.Bogus.*` 缺失键、两条消费级 8 天断言吐出 `09-03` / `2026-09-03`。回滚后复跑 **1635/1635** —— 两条守卫都确实会咬。
- **测试环境 CurrentUICulture 是 zh-CN**：消费级断言用 `string.Format(_loc["Settings.Analytics.DaysAgoFormat"], 8)`（≈`8天前`）而非硬编码英文，红证明的失败信息实证了这点——写死英文会假红。
- **阈值为什么不做成入参**：参数化只会把「漂移」改名成「声明」。真正的机制保证是**调用点无处安放第四个数字**（模块里只有一个常量）。分面差异（键族 + 绝对格式）才留参数——那是「详情卡详述 vs 密集表格紧凑」的真实排版差异。
- **删不可达分支属 #3 而非越界**：`PluginViewModel._formatter` 是唯一构造器无条件赋值的 `readonly` 字段 → `LastUsedSummary` 的 `??` 右支不可达，而私有 `FormatTimeAgo` 的唯一调用点就是该右支。删掉 `FormatTimeAgo` 后 8 处 `??` 必然连带删除，否则编译不过 —— 这是「3 份 → 1 份」的完整收口。
- **缺键不再靠内联英文兜底**：`ILocalizationService` 缺键返回**键名本身**（`LocalizationService.cs:48`），可被守卫发现。改为守卫断言「formatter 请求的每个键在两个 resx 都存在」，且**键名从实现推导**（每桶记录一次请求）→ 守卫不会与实现一起漂移。两条 `RelativeTimeKeyPrefix` public const 是守卫的绑定锚点。
- **测试命名空间**：测试目录镜像生产树 `Core/Formatting/`，但命名空间**去掉 `Core` 段**（`Pulsar.Tests.Formatting`）——`Pulsar.Tests.Core.*` 会遮蔽 `Pulsar.Core.*` 致生产类型解析失败。同 `Tests/Core/Rendering` → `Pulsar.Tests.Rendering` 的既有约定。
- **工具坑（沿用）**：bash 本次可用（`cat` / `grep` / `find` 正常），但 `PowerShell` 工具的 stdout 仍不回传 → 一律 `*>` 重定向后 Read 日志（GBK，Grep 匹配 ASCII 词会全 miss）。
