## Session (09:0x–09:5x · 插件页「内置/外部」标签头不可点击 —— 根因诊断 + 修复 + 全类守卫)

**用户指令**
- 设置页 → 插件标签页，「内置」「外部」两个按钮无法点击；找根本原因，并一并修复类似问题。指定走 `.agents/skills/diagnosing-bugs` 流程。

**诊断路径（diagnosing-bugs 六阶段）**
- **Phase 1 反馈回路**：`Pulsar.E2E` 真实鼠标点击 workflow（`artifacts/settings-plugins-tabs.json`，15 步：launch → open-settings → 导航到插件页 → 断言内置默认 → 点「外部」→ 断言外标签安装按钮物化 → 点回「内置」→ 断言搜索框重新物化）。断言目标利用「WPF TabControl 只物化选中标签内容」的性质，命中缺陷本体。**非 `--low-interference`**（UIA Invoke 会绕过命中测试，遮罩/焦点类缺陷测不出）。为此给两 TabItem + 安装按钮 + 搜索框加了 `Pulsar.Settings.Plugins.*` AutomationId。**修复前 9 连红**（repro1–9，全在 `assert-external-selected`：点「外部」后安装按钮 8s 内从未物化）。
- **Phase 2/3 假设判别**：遮挡假设被三重证据排除（截图无遮挡、UIA bounds 无重叠、enabled=True）；「事件没到 TabItem」被 TabItem 级 `handledEventsToo` 探针排除（DOWN 到达且 handled=True）；「鼠标捕获被占」排除（`Mouse.Captured=null`）。焦点探针抓到决定性签名：点击后 `PagePreviewGotFocus new=ScrollViewer(chain=ContentSite ← Border ← Grid#Root ← TabItem ← TabPanel#HeaderPanel ← ...)`，**无任何以 TabItem 为目标的焦点事件**，无 `SelectionChanged`，UP 时 `isSelected=False`。
- **Phase 4 根因**：TabItem 视觉树 dump 显示 header ContentSite 的视觉子级是 ScrollViewer+ScrollBar（而 `Header` 实为 `System.String`，`contentSiteContent=System.String`）→ 资源链排查锁定 `Themes/DialogTemplates.xaml` 的**隐式** `DataTemplate DataType="{x:Type sys:String}"`（App.xaml 全局合并，为对话框长消息滚动而设）。字符串头被渲染成可聚焦 ScrollViewer → 点击时焦点被它截走 → 现代 WPF TabItem 的**焦点驱动选中**（`SetFocus() → OnPreviewGotKeyboardFocus → IsSelected`）断裂。`handled=True` 的来源也对上了：`TabItem.SetFocus()` 返回 `Focus() || setFocusOnContent`，点标签时键盘焦点在 NavigationViewItem（`currentFocus==null`）→ `setFocusOnContent=true` → `Focus()` 失败也返回 true。
- **Phase 5 修复 + 红转绿**：模板根 ScrollViewer 加 `Focusable="False"`。修复后回路 **2 连绿**（fix1 30.2s / fix-final 28.4s），焦点签名变为 `new=TabItem(...TabPanel#HeaderPanel)` + `SelectionChanged selectedIndex=1/0`——.NET TabItem 设计行为（Focus → 选中 → `MoveFocus(First)` 进新标签内容第一个可聚焦元素）完整走通。
- **Phase 6 清理**：全部 `[DEBUG-tabs]` 探针拆除（`git diff` 确认 .xaml.cs 零残留），干净构建复跑 E2E 绿。

**类似问题一并修**：隐式 String 模板是全应用作用域地雷（Expander 头/菜单头/tooltip 等一切字符串渲染位点同病），`Focusable="False"` 一处修复全类覆盖。新增静态守卫 `Pulsar.Tests/UI/ImplicitStringTemplateFocusGuardTests`（全源码 XAML 扫描：隐式 String DataTemplate 根必须 `Focusable="False"`；匹配集空 fail-fast）；**变异检查**：移除属性 → 恰好 1 条失败且报对文件与元素 → 恢复复绿。

## Session (09:5x · 插件页工具栏右缘溢出 —— StackPanel→Grid Star 列修复)

**用户裁定**：上一会话顺带发现的工具栏溢出，用户先质疑截图证据 → 复核确认成立（3× 放大裁剪 `artifacts/e2e-plugins-tabs/toolbar-right-edge-zoom.png`：System 片右侧按钮被裁剩细条；并纠正引用——1992 是 RootFrame 右缘，窗口本体右缘 2030，Refresh 右缘 2130 超窗口 100 物理px）。溢出只在 E2E 固定窗口尺寸（1000×700 DIP）出现，用户真机窗口更宽故不可见。用户随后拍板「继续修」。

**根因**：`SettingsPluginsPage.xaml` 工具栏（Grid.Row=1）是**水平 StackPanel**——无限宽测量子项、不收缩、不裁剪，窗口缩窄时整行右溢（e2ae5f7 挪独立行时引入）。设置窗口 `Width=1000 Height=700` 无 MinWidth，任意缩窄都会触发。

**修复**：StackPanel → Grid 五列（Auto|Star|Auto|Auto|Auto）；搜索框入 Star 列（`MaxWidth=240` 封顶 / `MinWidth=140` / `HAlign=Left`）——宽度不足由弹性元素吸收，Auto 控件永不被推出。注释里写明「此处禁用水平 StackPanel」及原因。

**验证（数值红绿对照，同窗口 1500×1050 物理）**：
- 修复前：Refresh (1969,419,161×54) 右缘 2130 > 窗口 2030；SearchBox 宽 360px。
- 修复后（`toolbar-fix1`，15 步 PASS 30.7s，含标签切换回归）：Refresh 右缘 1992 ≤ 2030（恰贴内容区右缘）；SearchBox 宽 222px（Star 列收缩生效）。
- 证据来源：workflow 新增 `dump` 步骤（PASS 也产出 UIA 树）→ `artifacts/e2e-plugins-tabs/toolbar-fix1/toolbar-uia-tree.txt`。
- build 0 警告 / 0 错误；全量测试见同日下文。

**方法沉淀**：E2E `dump` 步骤（`WorkflowRunner.cs` StepType.Dump）在 PASS 时也落 UIA 树 → 布局类缺陷可用「dump + 数值 bounds 对照」做红绿判据，不必靠失败截图。
