**关键决策 / 坑（archify 几何经验）**
- **sublabel 字号有 9px 上限**（不随文本缩短而变大），`minimumProjectedNodeTextPx` 的下界约束是 `scale≥6/9≈0.6667` → `viewBoxWidth ≤ 1395`（1440 视口 + sidebar）。这是可读性失败的真正约束。
- 标签默认锚点：竖直 `bottom→top` 边的标签锚在「源节点底边上方 6px」（压住源节点），需 `labelDy` 推入 gap；水平边的标签锚在路径 20% 处，过宽时会反压源节点，需 `labelDx`。
- `pipeline→perm` 与 `pipeline→loader` 共用 pipeline 右侧端口，靠 port spread 仍只拉开 15px → loader 标签用 `labelDy` 推走避让 perm 路由水平段。
- `ops→state` 边若走竖向走廊会横穿 `executor→pipeline` → 把 seam 列重排为 registry(top)/ops(mid)/executor(bottom)，ops 与 state 几乎水平对齐。
- 列间距按各标签实测宽度差异化分配（78/78/106/88/93），非均匀 gap 反而更省 viewBox 宽度。
- repo evidence 自动验证是杀手锏：`--repo-root` 让 archify 校验 `sources.path` + `line` 真实存在（不再「标注=装饰」）。
- 不读 renderer 源码也能修完：所有几何修改都从校验诊断的 `supportedFixes` 和 `evidence` 推断。
