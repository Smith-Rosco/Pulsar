## Session (11:5x) — tab 指示器「切到第一个 tab 无动画」修复（事件驱动重定位掐断动画）

### 做了什么
- **现象**：用户报「其他 tab 之间切换都有动画，但从其他 tab 切到第一个 tab（Slots）时始终是瞬态」。
- **根因**：指示器是两段式动画（stretch 120ms + snap 130ms），由 `ShellViewModel_PropertyChanged` 驱动；`SettingsWindow` 有 4 条重定位入口，其中**只有 `OnNavPaneLayoutUpdated` 有 `_isNavAnimating` 门**。`RepositionNavIndicator()`（DPI / 窗格开合 / 面板尺寸 / 导航项重建的公共入口）的延迟回调**没有门**，直接跑 `InitializeNavIndicator()` → `RepositionNavIndicatorImmediate(clearHeldAnimations: true)` → `BeginAnimation(prop, null)` 把在跑的 stretch 动画整段摘掉 → 指示器 1 帧内瞬移到目标。追踪现场：`PHASE1` 后 **1ms** 出现 `[SNAP] caller=InitializeNavIndicator clearAnim=True animating=True`，下一段 `PHASE2 atTop=69.7 atH=22.0`（已在终点）。
- **触发源**：用户环境在导航到 Slots 时会连发 7 次 `Window.DpiChanged`（23ms 内），排队 7 个延迟重定位 → 必然踩中动画窗口。**「第一个 tab」是伪线索**：真正的变量是「哪次导航恰好带出布局事件」。
- **次生缺陷（同轮修）**：phase 1/2 用 `From=null`（隐式 origin = 属性当前生效值），并发的重定位写入基础值后 phase 2 起点被改写 → 指示器「先跳后滑」。改为**显式 `From`**：phase 1 取当前生效值、phase 2 取 phase 1 的落点（帧间连续），顺带消除 `Height` 为 NaN 的取值崩溃通道。
- **修复（3 点）**：① `RepositionNavIndicator()` 延迟回调加 `if (_isNavAnimating) return;`（动画收尾 + `LayoutUpdated` 自愈接管）；② 两条 in-animation 退化路径（`boundsInvalid` / `NaN centers`）显式 `_isNavAnimating = false` 再 defer（放弃动画独占，否则会被自己的门拦下导致指示器卡住）；③ 显式 `From`。
