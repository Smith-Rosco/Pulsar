## Session (08:1x) — 半径双路径调查 + ADR-030 提案

### 做了什么
- **半径双路径分歧现场调查完成**（R1 遗留项）：Path A（`CalculateOptimalLayout`，默认槽径 50）vs Path B（`GetLayoutMetrics`，缩放槽径）。语义判定：**Path A 是幽灵半径**（N>8 实际槽径 <50，却按 50 推导半径），Path B 才是正确意图。
- 影响面实锤三处：①运行时死区失真——`GetDeadZoneRadius` 取 Path A、`_currentRadius` 取 Path B，`HitTestAt`（MenuSession:2092-2102）同函数两源混用，死区有效比率漂移 0.6536（N=10）→0.7154（N=12）；②编辑器环半径（Path A）与显示槽径（Path B 语义）自相矛盾且偏离运行时；③R1 后 `SlotLayoutEngine.cs` 需注释守卫双路径。
- **ADR-030 提案**（`Docs/decisions/030-wheel-radius-single-formula.md`，commit `66e277c`）：Path B 胜出——`CalculateOptimalLayout` 改用 `CalculateOptimalSlotSize(N)` 推导半径。运行时环视觉零变化；死区还原设计比率；编辑器自动同源。测试迁移 pose snapshot N=10/12 钉死值 + 新增双路径恒等断言。**Status: Proposed，实施等用户裁决。**

### 关键判断
- N≤9 两路径数值恒等（分歧仅 N=10/11/12）；运行时环视觉零变化是方案可行的关键——唯一可感知变化是 N≥10 死区缩小 3.95–9.58px（回到设计意图）。
- Alternatives 拒绝理由：Path A 胜出会放大真机环且违背缩放初衷；参数化=bug 合法化。
