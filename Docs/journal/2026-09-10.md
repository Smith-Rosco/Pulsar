## Session (08:1x) — 半径双路径调查 + ADR-030 提案

### 做了什么
- **半径双路径分歧现场调查完成**（R1 遗留项）：Path A（`CalculateOptimalLayout`，默认槽径 50）vs Path B（`GetLayoutMetrics`，缩放槽径）。语义判定：**Path A 是幽灵半径**（N>8 实际槽径 <50，却按 50 推导半径），Path B 才是正确意图。
- 影响面实锤三处：①运行时死区失真——`GetDeadZoneRadius` 取 Path A、`_currentRadius` 取 Path B，`HitTestAt`（MenuSession:2092-2102）同函数两源混用，死区有效比率漂移 0.6536（N=10）→0.7154（N=12）；②编辑器环半径（Path A）与显示槽径（Path B 语义）自相矛盾且偏离运行时；③R1 后 `SlotLayoutEngine.cs` 需注释守卫双路径。
- **ADR-030 提案**（`Docs/decisions/030-wheel-radius-single-formula.md`，commit `66e277c`）：Path B 胜出——`CalculateOptimalLayout` 改用 `CalculateOptimalSlotSize(N)` 推导半径。运行时环视觉零变化；死区还原设计比率；编辑器自动同源。测试迁移 pose snapshot N=10/12 钉死值 + 新增双路径恒等断言。**Status: Proposed，实施等用户裁决。**

### 关键判断
- N≤9 两路径数值恒等（分歧仅 N=10/11/12）；运行时环视觉零变化是方案可行的关键——唯一可感知变化是 N≥10 死区缩小 3.95–9.58px（回到设计意图）。
- Alternatives 拒绝理由：Path A 胜出会放大真机环且违背缩放初衷；参数化=bug 合法化。

## Session (11:4x) — slot 编辑 tab「内容溢出」修复（模态时代固定尺寸残留）

### 做了什么
- **现象**：用户报「编辑槽位的标签页内容溢出」。根因定位为**模态退役残迹**：`SlotConfigurationDialogContent` / `AddSlotContent` 仍带 `MinWidth="760" MinHeight="520"`（模态框时代的对话框固定尺寸），而 `69d89fe`（P3 模态退役）后二者唯一宿主已变成 transient tab 页 `SettingsSlotEditorPage`。
- **宽度算术**：窗口 1000 − NavigationView 展开窗格 250 − Frame Margin（`Pulsar.Pad.XXL` 24×2）= **≈702px** < `MinWidth` **760px** → 子元素按 760 排布，多出的 58px 无处可去；内容 ScrollViewer `HorizontalScrollBarVisibility="Disabled"` 连横向滚动条都没有 → **右侧状态徽标 / IconSelector 被静默裁掉**（纵向有 Auto 滚动条，安全）。
- **修复**：两处根元素 `MinWidth/MinHeight` 删除，改为设计期孪生 `d:DesignWidth="760" d:DesignHeight="520"`（尺寸交给 Frame/Page 裁决），并各留注释说明「P3 后不得再钉固定尺寸」。
- **回归守卫（新增用例）**：`SettingsLayoutGuardTests.Tab_hosted_dialog_contents_do_not_pin_a_fixed_dialog_size`——从页 code-behind 的 `new Dialogs.Contents.X()` **自维护地**解析被承载集合（新增复用点无需改测试），只扫**根标签**（内层 `MinWidth`（如 90px 标签列）合法），先 strip 注释（注释里就写了 `MinWidth`）。含「守卫的守卫」：匹配集合为空即失败，防改名后静默空转。
- **变异检查**：临时把 `MinWidth="760"` 加回 → 测试红且报 `Views\Dialogs\Contents\SlotConfigurationDialogContent.xaml: MinWidth="760"` → 撤销后复绿（4/4）。
