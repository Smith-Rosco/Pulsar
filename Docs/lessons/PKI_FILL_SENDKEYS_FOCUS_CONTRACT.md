# `pki/fill` 是纯键盘注入——焦点即生死，页面必须满足 SendKeys 契约

> 2026-09-07 · 来源：`Docs/demo/lesson.md` §2 + §8（演示视频三《登录，只要一滑》录制排障）。

## 症状

1. 轮盘执行「登录」槽位后什么都没填进去。
2. 或：重构/换皮的登录页上注入脚本全部失灵，旧页面上却一直正常。

## 根因

### `pki/fill` 走 SendKeys，不定位元素

- 注入序列是 `账号 → TAB → 密码 → ENTER`，纯键盘事件，**不查找窗口/页面元素**；
- 光标不在用户名框里，整条链路就全部打空——呼出轮盘、切标签页后焦点丢失即失效。

### 换皮页面破坏键序契约

- `pki/fill` 依赖目标页的**隐式契约**：`#username` → TAB 焦点链 → `#password` → ENTER 触发提交。
- 只靠按钮 `onclick` 处理登录的页面，SendKeys 的 ENTER 在输入框里触发的是**表单隐式提交**，按钮 onclick 不会被调用 → 填了但不提交。

## 修复（目标页面侧的契约清单）

1. 登录输入框加 **`autofocus`**，从根上兜底（呼出轮盘、切标签页后焦点仍在框内）；手动补点一次输入框作为保险动作。
2. **ENTER 必须能提交**：用真 `<form>` + `type="submit"` 按钮 + `onsubmit` 处理，不能只靠按钮 `onclick`。
3. **重构演示页/目标页前，先列出契约清单**：选择器列表（`#username` / `#password` 等）、TAB 焦点链顺序、ENTER 行为、`id` 清单；重构后 grep 逐项回验。复制文件改名 ≠ 复制完成，内容要逐页核对。

## 适用范围

该契约对**非网页目标同样成立**——`pki/fill` 的注入发生在前台窗口的键盘层，任何「有账号框 + TAB 可达密码框 + ENTER 可提交」的桌面软件登录窗都适用；反之，目标软件若 TAB 链不标准，需要先验证键序。

## 排查入口

| 信号 | 检查 |
|---|---|
| 填充完全没反应 | 99% 是光标不在输入框——点一次输入框重试 |
| 填了但不提交 | 页面是否只靠按钮 `onclick`；改成 form submit |
| 换皮后全部失灵 | grep 契约清单逐项回验 |
